Blocker 多 Google Play 政策與上架要求

targetSdk 必須升級至 35 已完成
Google Play 自 2024/08 起要求新上架 App 的 targetSdk 至少為 34，2025 年起則必須為 35。
已升級至 compileSdk = 35、targetSdk = 35，同步處理了 API 35 的 breaking changes：
• onBackPressed() → OnBackPressedCallback（predictive back 支援）
• FLAG_FULLSCREEN → WindowInsetsController
• NetworkInfo → NetworkCapabilities
• AGP 升級至 8.5.2、Gradle 升級至 8.7
缺少隱私權政策 已完成
App 使用了網路權限、推播通知、收集裝置 FCM Token 並傳送至自建伺服器。Google Play 要求必須提供隱私權政策頁面 URL。
已建立隱私權政策頁面：stvfu.com/comic/privacy.html
• 涵蓋 FCM Token、IP 位址、Cookie、離線快取等所有資料收集項目
• 說明用途、保留期間、App 權限、第三方服務（Firebase）
• 明確聲明不收集 PII、不使用廣告追蹤、不分享資料給第三方
內容分級問卷 必須
上架時需填寫 IARC 內容分級問卷。同人誌內容如包含暴力、性暗示等，需如實填寫，否則可能被下架。
尚未評估作品內容的分級。部分同人誌可能涉及 Teen 或 Mature 分級。
逐一檢視各作品是否含有需要分級的內容，在 Google Play Console 如實填寫問卷。若有成人內容則需標記為 Mature 17+。
版權與智慧財產權風險 已完成
App 內含多部基於知名 IP 的同人作品（鬼滅之刃、寶可夢、我推的孩子、暗殺教室、飛天小女警等），在 Google Play 上架可能觸發版權審查或收到 DMCA 通知。
實作了多層防護機制：
• 作品新增 type 欄位（original / doujin），從資料層分離原創與同人作品
• App 透過 ?type=original 進入，伺服器端過濾，預設僅回傳原創作品，同人作品完全不出現在 App 頁面中
• 網頁版（/comic/）不受影響，照常顯示全部作品
• 場次限定：通關密語解鎖機制（unlock.php），到場次攤位取得密語後可在 App 內解鎖瀏覽同人作品，Cookie 有效期 90 天
• 後台可管理密語內容、多組密語、啟用/停用開關
App 簽署金鑰（Signing Key）必須
上架 Google Play 需使用正式的 Release 簽署金鑰產生 AAB（Android App Bundle），不能使用 debug key。
目前僅有 debug APK（comic_punch_v2.0_debug.apk），未設定 release signing config。
在 build.gradle.kts 新增 signingConfigs 設定，產生正式金鑰（keystore），並妥善保管。建議啟用 Google Play App Signing。
需產出 AAB 而非 APK 必須
Google Play 自 2021 年起要求新 App 必須以 AAB（Android App Bundle）格式上傳，不接受 APK。
目前只產出 APK 檔案。
使用 ./gradlew bundleRelease 產生 AAB 檔案。
WebView 為主的 App 可能被拒 已完成
Google Play 的 Minimum Functionality 政策明確規範：「僅將網站包裝為 WebView 而未提供 App 特有功能的應用程式」可能被視為 spam 並遭拒絕。
App 已具備多項網站不具備的原生功能：
• FCM 推播通知（新章節更新即時提醒）
• 離線閱讀（下載章節圖片至 App 內部儲存，無網路時可閱讀）
• 通關密語解鎖（場次限定互動機制）
• App 版本更新檢查（啟動時自動偵測新版本）

需修正 技術問題

通知圖示使用系統預設 建議
推播通知使用 android.R.drawable.ic_dialog_info（系統預設的「i」圖示），在不同裝置上顯示效果不一，且不專業。
NotifyMessagingService.java:57 使用系統 drawable。
設計專屬的通知小圖示（24x24dp，白色 + 透明底），放置於 res/drawable/，並在 NotificationCompat.Builder 中使用。
Token 更新未重新註冊 建議
FCM Token 會定期更新，但 onNewToken() 只有 Log 輸出，未將新 Token 送回伺服器，導致推播失效。
NotifyMessagingService.java:37 — onNewToken 僅記 Log。
在 onNewToken() 中呼叫 sendTokenToServer()（需抽成靜態或共用方法）。
使用已棄用的 onBackPressed 已完成
onBackPressed() 在 API 33+ 已被標記為 deprecated，應改用 OnBackPressedCallback。
已改用 getOnBackPressedDispatcher().addCallback() 搭配 OnBackPressedCallback，支援 predictive back gesture。
使用已棄用的 FLAG_FULLSCREEN 已完成
WindowManager.LayoutParams.FLAG_FULLSCREEN 在 API 30+ 已棄用。
已改用 WindowInsetsController.hide(WindowInsets.Type.statusBars())，搭配 BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE。
缺少 ProGuard / R8 混淆設定 加分
Release 版本應啟用程式碼混淆與壓縮，減小 APK/AAB 體積並增加逆向難度。
build.gradle.kts 中沒有 buildTypes 設定。
新增 release buildType，啟用 isMinifyEnabled = true 與 isShrinkResources = true。
缺少 xxxhdpi 解析度的啟動圖示 加分
高解析度裝置（如旗艦機）需要 xxxhdpi（192x192）的圖示才能清晰顯示，且目前的圖示只是簡單幾何圖形。
圖示只提供到 xxhdpi，且是程式產生的幾何 vector，無品牌辨識度。
設計正式的「猛少女之拳」品牌圖示，並使用 Android Studio 的 Image Asset Tool 產出所有尺寸。Google Play 另需 512x512 的高解析度圖示。

體驗 使用者體驗問題

無離線或無網路提示 已完成
App 完全依賴網路載入 WebView 內容，斷網時顯示 WebView 預設錯誤頁面（灰底白字），體驗極差。
已實作完整離線體驗：
• onReceivedError() 偵測無網路時自動顯示離線首頁，列出所有已下載章節
• shouldInterceptRequest() 攔截 reader.php 請求，離線時回傳本地生成的閱讀器 HTML
• 已下載章節的圖片從本地快取載入，支援完全離線閱讀
• 離線首頁提供「重新連線」按鈕
無啟動畫面（Splash Screen）加分
App 啟動時直接顯示空白 WebView 等待載入，冷啟動會有明顯白屏。
未實作 Splash Screen。
使用 Android 12+ 的 SplashScreen API，設定品牌色背景 + 圖示，讓啟動過程更流暢。
推播點擊只開啟首頁 加分
收到推播通知後點擊，只會開啟 MainActivity 首頁，無法直接跳轉到對應的更新內容或章節。
NotifyMessagingService.java:52 Intent 無附帶任何 extra 資訊。
在推播 payload 中加入目標 URL，Intent 加入 extra，MainActivity 收到後自動導向對應 WebView 頁面。
缺少載入進度指示 加分
WebView 載入頁面時沒有任何進度條或 loading 動畫，使用者不知道是否在載入。
利用 WebChromeClient 但未覆寫 onProgressChanged。
在 layout 頂部加入 ProgressBar，透過 onProgressChanged 更新進度。

安全 安全性問題

Token 註冊 API 無身份驗證 建議
任何人都可以向 /api/register_token.php POST 任意字串，可被用來灌假 Token，導致推播時大量失敗、浪費 FCM 配額。
register_token.php 只檢查 token 是否為空，無任何驗證。
加入簡單的 API Key 驗證（App 端 Header 帶 key），或驗證 Token 格式是否符合 FCM Token 規範（約 163 字元的字串）。
推播 Server 無清理失效 Token 建議
sendToAllDevices() 逐筆發送但失敗時不刪除失效 Token，隨時間累積大量無效 Token，推播越來越慢。
fcm_send.php:70 失敗只計數，不處理。
當 FCM 回傳 404（Token 已失效）或 UNREGISTERED 錯誤時，從資料庫刪除該 Token。
FCM Project ID 寫死在程式碼中 加分
fcm_send.php:41 將 Firebase Project ID 直接寫死為 'ignore-comic'，應從 config 讀取。
硬編碼在原始碼中。
改為從 config.php 的 FIREBASE_PROJECT_ID 常數讀取（該常數已定義但未被使用）。
